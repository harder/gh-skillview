# Ownerless local source switching

This workflow reviews replacement of one physical ownerless local installation
from a different existing durable ordinary local source. It is baseline-less:
installed I and selected C are real captures; the previous recorded address is
placement evidence, never a historical base. All consumers remain attached to
that physical installation. Git-managed sources, native owner transitions,
per-consumer detachment and fork creation remain unsupported. M08 stays incomplete.

Use `source-switch-plan --path <installation>` (or exactly one `--install-id`)
with `--new-source <absolute directory>`. Global scan/workspace/profile options
precede the command. CLI JSON exposes separate `localSourceSwitch` and
`localImport` evidence and `localSource` freshness, without fabricated revision,
base or pin records. A saved schema6 plan has purpose `switch-local-source` and
requires explicit `replace-local-source-retain-original` approval plus its exact
fingerprint. The inspect/apply/recover/undo command families refuse other purposes.
Schema1–5 omit the new field and retain their old hash domains.

In Installed, **T** opens the selected physical installation's transition modal;
**R** remains same-source reimport and **K** remains offline package checking.
Typing those letters in the filter edits the filter. Enter the durable new path
and Prepare, inspect all changes/consumers, then approve retention and Apply.
Editing the path, saved ID or hidden-directory option closes approval. Reopen a
saved ID explicitly with Inspect; reopening never stages another candidate.
Worker ownership includes queued completion, cancellation and reconciliation.

The source must have a regular root `SKILL.md` with the same authored name, no
nested or case-variant `SKILL.md`, no payload/final-source links, and no owner
records. Ordinary ancestor aliases are resolved natively and rechecked. A copied
source may carry an absent or absolute historical local-path; its exact observed
scalar is retained separately. Mixed remote/pin tracking refuses rather than
stripping it. The candidate copies captured C and splices only root local-path to
the durable selected address, preserving BOM, CRLF, comments, authored content and
supported descendant metadata. It retains I root privacy. Actual gh staging is
an isolated compatibility witness: gh may rewrite YAML/modes and omit empty
directories, so its output is not the candidate. Installed-only files may be
removed by the reviewed replacement; the exact original native objects remain
retained for undo. New active IDs/timestamps are disclosed.

Before any private writes or gh work, the old address receives a separate native
placement observation. Windows initial placement capture may restart a maximum
of four complete walks from the volume root when a held parent's generation
changes during that unfinished read-only observation. Every failed attempt
releases its handles; no child/evidence is reused and every retry checks
cancellation. Alias, type and policy refusals are not retryable. A completed
lease still requires exact fresh-address/anchor comparison; this is not a retry
of stale approval or a mutation. Shared system-temp ancestor churn in parallel
tests must not be mistaken for cancellation reaching the payload checkpoint.
A genuinely absent path requires an explicit first
missing child under a held existing canonical directory; the remaining lexical
suffix is unreachable below that boundary. Access/I/O errors, broken links,
non-directory ancestors, ambiguous resolution and bounded exhaustion refuse;
existence-false and lexical fallback are not missing evidence. On Linux the placement walk starts at a held filesystem root and uses verified
`openat2(RESOLVE_NO_XDEV)`. Ordinary ancestor links use bounded, held
`readlinkat` evidence and restart the same checked root walk; absolute link jumps
never waive the boundary. Raw link targets with dot/dotdot components and external
addresses with dot components refuse rather than normalizing across unresolved
links. Expansions share 16 links, 128 walked components and 16 KiB raw-target
budgets; paths are limited to 32 KiB UTF-8. Parent/link full identity/generation
and raw target bracket each restart. Broken targets cannot become missing suffix
evidence. The returned held anchor retains the exact original recorded lexical scalar for
fresh revalidation; canonical projection remains a separate field. Bind/mount
transitions refuse, including legitimate old/new/state paths on another mounted
filesystem; device equality alone is not sufficient. This bounded contract does
not infer physical exclusion from alternate bind-mount namespace paths.
Old and new lexical and canonical addresses must exclude private stores and installed payloads.
The old content is never read as a base; changing it does not become a content
freshness dependency. Placement identity/mapping and the missing boundary are
rechecked around private admission and before the first retain. This is an
observed namespace policy boundary, not a promise that a later external alias
still denotes the same place or that external paths cannot change concurrently.

I/context/all consumers and full selected-C native capture must remain fresh
through the first actual retain, including an unfinished retain-intent with I
still present. Once I has actually moved, recovery and undo use frozen archives
and topology even if both external sources disappear. Inspection reports
`current`, `stale`, `unavailable` or `not-required-after-retain`; a stale external
observation does not veto frozen recovery. Undo restores I and its previous exact
tracking, without writing either external source. Final native name intervals
and platform publication limits remain those of recorded restoration.

An exact already-recorded source request refuses with reimport guidance before
gh/private staging; it does not establish that I is current. A different recorded
address is a reviewed tracking change even when authored bytes are equal. Aliases
do not establish independent fork ancestry. Existing preview coordination,
logical working reservation and retained-plan quotas apply; failed/unknown child
output reserves the full working budget. This is not an OS disk quota. Captures
are copied through held archive authorities into a new final operation and
recaptured; active state directories are never renamed. Retained failures expose
their exact ID/path. No client or payload code executes.

Local tests qualify their exact source and environment separately from native
App/extension proofs. Four-RID minimum/current-gh lifecycle and real old-native
schema1–5 compatibility require actual final-source CI evidence; the design and
local refusal tests alone do not establish those gates.

New product plans also freeze installed/candidate source-review archives. Review
their changes and omissions, then declare the exact source review separately
from retention approval with `source-switch-ack-source`. The local dialog
requires both approvals and closes both when ID, source or hidden-directory
options change. A declared review supplies no authenticity or safety assurance.
The native proof includes a fresh ready plan recovered through the real workflow
coordinator with its source-review declaration, followed by exact native undo.
That proof is pending until its final native hosts execute. Compatibility with
pre-review schema6 plans additionally needs an actual final PR70 native producer;
source inspection and schemas1–5 restart proofs do not substitute for it.

Frozen schema5 compatibility evidence retains the complete bounded `gh --version`
stdout after trimming its outer whitespace, including the release URL and internal
line endings, exactly as the native producer records it. Check the staged binary
hash independently; a first-line banner is not the saved version witness.

Windows restart-bound fixtures perform real namespace changes and explicitly
advance the private parent's native creation-time generation, checking it back.
Rapid directory-entry changes can share a timestamp, so clock progress alone
cannot deterministically exercise every retry. Production generation checks and
the four-attempt bound remain unchanged.
