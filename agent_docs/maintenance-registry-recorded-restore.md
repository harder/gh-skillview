# Bounded registry-recorded restoration

`registry-restore-*` is an explicit source-selection workflow for one ordinary
nonnested physical copy with MissingSkillMd or UnparsableFrontMatter. Parsed
InvalidMetadata is eligible only when surviving tracking and name agree with the
record. NameMismatch, links, managed/exclusive/read-only owners, conflicts,
partial inventory and unknown policy refuse. No maintenance recommendation grants
authority. Installed More actions hands off the exact copy to fresh inventory.

Require exactly one already-attached compatible nonexclusive `gh-vercel-global`
schema3 claim: sourceType github, recorded-git-tree with a full 40-hex tree, no
owner diagnostics, selector equal to candidate name and physical leaf. Never
attach an otherwise unassociated record by name. Preserve raw selector/skillPath
in Owners; require the exact terminal `/SKILL.md`, remove only that suffix, then
use existing NormalizeSubpath. Validate repository source/URL agreement.

A global registry record has no destination. It cannot establish unique
placement or authorize stale-record deletion. Review must say:
“Replace with the version recorded in gh’s registry for <name>; the registry does
not record which folder it belongs to.” Surviving non-SKILL.md entries must match
candidate bytes, types and modes exactly. With no surviving file corroboration,
say so explicitly. Never claim the original installation here is known.

Use existing GhRecordedTreeStager identity verification and RecordedTrackingWriter.
Pins resolve through the existing exact-tag resolver, requiring its resolved
subtree equal the recorded tree. An unpinned record produces absent GithubRef;
never infer latest, a branch, a tag or a commit from a tree or damaged metadata.
Raw Git blob hashes, source trees, gh-materialized bytes and native digests remain
separate domains. No normalization of original/corroboration evidence is allowed.

The new `restore-registry-recorded` purpose is a schema1 sibling with a null-omitted
`RegistryRestore` policy. Subject.Metadata and Subject.Agents remain observed damaged evidence. The policy
also freezes possible gh catalog memberships at the exact captured native address
from existing GhPlacementCatalog user placements under the captured child
context. gh omits missing-SKILL rows and can report these memberships after repair.
They attest no installed/enabled/active agents and add no physical address.
Recompute their complete exact set on saved open; ExecutionSubject includes them
so the unchanged consumer/context checks cover both pre/post-metadata inventory.
The review presents them separately from observed original consumers.
Subject.Metadata remains observed damaged metadata;
RegistryRestore.DesiredMetadata is synthesized separately. Subject(plan) retains
its historical semantics; ExecutionSubject projects desired tracking only for
this purpose. Existing schema1–6 purpose/hash/parser/native behavior stays exact.
Old readers reject the new purpose/field. New readers reject this policy on any
ordinary purpose. Ordinary missing-ref restore/update/unpin admission is unchanged.
IsRevisionUpdate remains false.

Only this purpose uses the dedicated OpenRegistryDamaged native move entry. Its
only policy exception is absence of SKILL.md; full held identity/generation,
nonlink directory, Git, containment, native rename, metadata and cancellation
checks remain. Ordinary Open still requires SKILL.md. Original entries may be
empty only under this purpose's validation. Raw CaptureRawInto/archive capture
never parses/normalizes the damaged file; historical CaptureInto is unchanged.
Both original and candidate need complete supported native metadata. Freeze full
raw archives for source review and revalidate both live slots' metadata through
held native objects on every observation/transition. Linux unknown trusted-xattr
coverage refuses separately from privileged proof success.

The owner registry is not written: same source/tree/pin, no owner transition.
Capture/recheck contextual ownership and consumers at every existing boundary.
Review frozen source independently from retain-original approval. Apply binds
exact ID/fingerprint; recovery/Undo bind a fresh inspection fingerprint. Retain
both native directories and raw damaged topology across restart. Preparation
failure/cancellation retains private evidence and identifies its location.
Native outcome and inventory reconciliation are separate; do not erase native
success or retained Undo evidence when post-attempt verification is incomplete.

The dialog's read-only source pane leaves Tab/Shift+Tab to ordinary focus
traversal, including reverse/wrap and disabled-control skipping. Scrolling and
Home/End remain in the pane. Moving focus never checks either approval; fresh
preparation/inspection clears both, and native actions retain their existing gates.

After an unpinned repair, ordinary SkillView update/version choice remains refused
and availability unsupported with remove/reinstall guidance where admitted.
Actual gh 2.97.0 and 2.103.2 update with only github-ref absent was independently
proven for bounded intact-tracking + matching-registry cases in the 2026-10-27
preflight. That does not grant planner admission or justify updating during repair.

`tests/native/prove-registry-recorded-restore.py` uses actual gh installs (never a
fabricated positive record), both required gh versions, separate approvals,
unchanged registry bytes/native owner file and exact native Undo for pinned and
unpinned corrupt YAML, missing empty and missing corroborated copies. The genuine
cli-exercise .gitignore is retained as corroboration; nested resource directories
are preserved outside the damaged subject to keep discovery nonnested. Tests
never execute source payloads. Optional proof host kills after retain/install;
old-reader failures are checked against a frozen reviewed binary. The sources
CI family runs both hosts/four RIDs, with Linux refusal and privileged lanes.

On saved open, reparse the held immutable archives' raw SKILL.md bytes and bind
both observed validity/metadata and desired metadata to them. Missing originals
must actually omit SKILL.md; malformed UTF-8 stays raw unparsable evidence. Reject
malformed policy collections/pin members rather than admitting a synthetic subject.
The catalog-membership binding and preservation of all old purpose behavior are
mandatory independent safety-review topics.
